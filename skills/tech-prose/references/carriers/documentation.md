# 技术文档

## 按载体定侧重

- **README**：直接说明用途与操作，读者能照着跑起来。
- **API 参考**：准确表达参数、结果与限制；原文缺的列进缺口，不猜。
- **设计说明**：讲清理由与取舍，以及被放弃的备选。
- **操作说明**：用明确动作，步骤可复现。

人称：步骤式与教程用第二人称（“你可以……”），参考式用第三人称陈述，不写对话式开场。不清楚读者是谁时，按“下一个接手这段代码的人”写。

## 结论先行

- 每节第一句给出本节的结论或动作；结论需要证据时，证据紧随其后。这是起草时的写法：改写现有段落不搬句调序，只指出结论被埋在了后面。
- 标题写读者能得到什么：`重试在高负载下退化为每 30 秒一次` 优于 `重试在高负载下的行为`，后者优于 `重试机制`。
- 前置条件、限制与注意事项出现在读者遇到它们之前。这是起草时的写法；改写时只指出位置问题，搬移按结构授权处理。

## 强主张要有依据

起草时，强主张必须带依据，否则降级为假设并标记。改写已有文档时，缺依据的强主张保留原文，把待核查项写进报告。

先给结论，紧接着给依据（代码、issue、trace、指标或示例）。

```
弱：这条链路已经很清楚。
强：写入与读取之间的一致性有风险：从现有调用看，A 先写入 task state，
    B 再从同一个状态入口读取结果。
```

证据不足时，降级为带标记的假设：

- `当前证据更支持…`
- `从这几处调用看…`
- `这里先按假设处理…`
- `还需要用…验证`

反过来，把有依据的不确定性连同限定一起保留：`可能`、`通常`、`尚未验证`、`约 5 秒`、`advisory` 都是信息。

## 示例

- 起草时用能证明论点的最小例子，去掉无关的脚手架；改写现有示例不删内容。
- 示例里的命令、参数、路径与代码要和原文逐字一致，不擅自改写；能否直接跑无法当场验证时标为缺口，不改成看起来能跑的写法。
- 必要时给一个反面例子说明常见错误。

## 读者与任务完整性

起草或审阅时，检查材料是否足以让目标读者完成任务：读者已知哪些概念；在哪个目录、工具、环境或身份下操作；占位符替换成什么；怎样确认结果。不是每篇文档都需要写全这些项，只检查任务实际依赖的部分。受众差异会改变交付时才提最小问题，不固定发问卷。

审阅只报告缺口；起草依据材料补齐。改写不因发现缺项自动扩写或搬移内容，扩写按本次授权及“压缩保限制，扩写补事实”处理。没有执行记录时，不把示意输出说成实测结果；文档里的命令是审查对象，不因审阅或起草请求自动执行。

## 链接与图片

- 链接文字说明目标，`部署文档` 优于 `点击这里`、`详见此处`。
- 信息图要有替代文本，说明图里的信息，不写 `图片`。装饰图在格式支持时用空替代文本，保留无障碍标记。
- 缺图片材料时标为缺口，不描述图里可能有的内容。
- 位置、颜色或形状不应是唯一定位线索。已有控件名称时用名称定位；名称未知时列缺口，不猜。不禁用有明确指代的“上图”“下图”。
- 关键事实只在截图里、正文没有文字承接时，报告缺口；获准补写且能核实图片内容时补充必要说明，不机械复制全部图片内容。

## 术语

- 一个概念只用一个词。首次出现定义缩写，除非可以确定读者已知。
- 中英文混排时选一个主形式，首次出现再给另一种称呼。
- 代码里的标识符、字段名、状态值保持原样，不翻译不改大小写。
- 下列内容用代码字体：文件名与路径、类名与方法名、HTTP 状态码、命令、字段名、占位符。普通英文单词不进代码字体。
- 加粗留给界面元素与定义词条，斜体留给首次引入的术语、变量与作品名；其余靠句子本身。具体用什么标记跟随项目与载体惯例。

## 混合文档的编辑边界

文档可能同时包含正文和由机器解释的语法：frontmatter、MDX/HTML 组件与属性、模板变量、include 或短代码、显式锚点。按字段用途与本次授权判断可否修改，不按“看起来像文案”判断。技能的 `description` 可能影响触发，标题可能影响自动生成的锚点。

默认润色自然语言正文，保留键名、组件名、变量、控制指令、锚点及属性中的机器值。文字字段与属性中的展示文案也须核实用途后，按本次范围处理。触发范围或行为的变化按既有动作边界处理，不视为等义润色。结构调整导致的内部链接更新按本技能 `SKILL.md`“改动前的三个判断”中的判断一处理，并核对引用的目标与含义。格式或字段作用无法确认时保留原样、列为缺口，不猜测转换格式。

## 失败路径

文档里描述失败、限制与回滚时，恢复路径与升级指引（“请联系管理员”“提交工单”）是读者能采取的动作，删掉等于删信息。

写清失败后状态如何、能否重试、重试是否安全。材料里没有就列缺口，不补。

错误信息的文案规则见 `ui-copy.md`，命令行报错见 `cli-output.md`。

## 压缩保限制，扩写补事实

- **压缩**：删除冗余、合并重复条件、去掉不需要的背景。保留全部限制和例外。
- **扩写**：补前置条件、示例、边界和恢复路径。补的内容要有依据——用户材料、已核实的源码或文档；原文没写不等于没有依据，但依据本身也不能靠推断补。

两条都保持事实、术语和规范强度不变。
