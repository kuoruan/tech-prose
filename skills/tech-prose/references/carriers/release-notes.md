# 变更与发布说明

处理变更片段（changeset、news fragment）、变更日志（changelog）与发布说明（release notes），包括据这些材料起草 GitHub Release 的说明正文。跟随项目现有格式，不把所有发布说明改成同一种模板。

## 条目怎么写

原因、后果与升级动作按已提供或已核实的材料写；缺乏依据时列为缺口，不自行补全。

- 写可观察的变化：什么变了，对谁生效，哪些条件影响结果。原因与升级动作按需补充，不强制每条填满固定模板。
- 区分修复错误与有意改变行为，不都写成“优化”。不把提交标题或 PR 标题直接升格为性能、安全或兼容性保证。
- 破坏性变更说清受影响接口、后果与必要的升级动作。复杂步骤有可核实材料才链接，没有就列缺口。
- 压缩时保留废弃、移除、限制、前提、例外与必要迁移。多包汇总保持包与影响的对应，不合并成泛化结论。

## 变更片段

只润色本次授权的文字，保留片段文件名、机器字段与标记语言。分不清字段用途时保留原样并列缺口。

- **Changesets**：YAML 头部元数据中的包名及 `major`、`minor`、`patch` 表示发布意图，不属于正文。润色 Markdown 摘要正文时不改这些字段。版本升级级别不能确定最终版本号，也不能证明已经发布。
- **Towncrier**：文件名可承载编号或唯一标识及分类，如 `1234.bugfix.rst`。编号与分类不改，末尾后缀也不因看似无用而删除。正文按项目指定的 reStructuredText 或 Markdown 写，不擅自转换。
- **Reno**：YAML 文字值可包含 reStructuredText。保留键名、值类型、缩进、列表结构、块标量标记（`|`、`>`），以及 RST 角色、指令与链接，不把这些语法当成文案润色。

未确认哪些片段属于目标版本时，列缺口；不按目录中的全部片段推定发布范围。润色不授权使用片段生成版本记录、删除片段、运行生成器或修改其配置。

## 变更日志

- 跟随项目的分组、标题、顺序与语言。Keep a Changelog 的六类与版本逆序是一种惯例，不强制覆盖 Changesets、release-please、git-cliff 等工具的生成格式。
- 润色时保留版本、日期、分类、条目前的包或作用域（scope）归属标记、生成器标记、锚点与链接目标。
- 分类标题可重复出现，不为标题唯一而改名或合并。不顺带改写请求范围外的历史。
- 生成器注释和插入点标记可能供工具定位或解析，不删除。需要改分组或重排历史时，按结构授权处理，不把它们当成措辞修改。
- 区分废弃与移除、预发布与稳定版、待发布与已发布；保留 `Unreleased`、`YANKED` 等状态。替代方案、移除时间线、受影响与修复版本、CVE 编号都按材料写，不自行补全。

## 据材料起草发布说明

先确认目标版本、涉及的包，以及有必要区分的分支与材料范围。范围含糊且会改变输出时才提最小问题，不固定发问卷。

- 从已分版本的变更日志起草时，只取目标版本的条目，不混入其他版本。`Unreleased` 与待汇总的变更片段只有明确属于本次范围时才纳入；版本或发布状态未确定时，作为草稿并列缺口，不宣称已发布。
- 生成新正文可按请求去重归类，但保留不同包、不同条件的影响与全部升级风险。亮点可精选，破坏性变更、废弃、移除、限制与必要迁移不能因此漏掉。
- GitHub 原生自动说明以合并的 PR、贡献者和变更比较链接为素材，不是提取仓库 `CHANGELOG.md` 的正文。仍须核对范围与表述，不把自动结果当成已验证结论。
- PR、贡献者、比较链接、性能指标与兼容承诺都须有依据。材料缺失就列缺口，不按常见格式凑全。
- 起草新正文不自动授权改写来源文件或历史，也不授权改版本、打标签、创建或发布 GitHub Release、保存远端草稿或配置 CI。

独立迁移指南或安全公告等文档按需同时参考 `documentation.md`；本文件只处理变更摘要及其关联说明，不代替事实核实或安全审查。
