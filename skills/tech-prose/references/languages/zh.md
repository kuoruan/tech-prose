# 中文技术文字的具体问题

配合 SKILL.md 使用。铺垫、对偶、排比这类跨语言模式在 SKILL.md 的“冗余与形式化表达”里；这里处理中文的词组与句法。

**总原则：**先判断这句话有没有真实信息。没有信息就删除；有信息，就围绕具体的人、动作、条件、数据改写。单条信号先保留，同一段多条一起出现才构成证据；单条已明确损害准确性或可读性时直接改。按词表做机械替换无效：形容词被替换，句子仍然空洞。

## 叙事填充

只管理文章流程、不提供事实的句子。默认动作是删除，使后一句事实成为开头。

- `接下来我们来看 X`
- `聊到这里`
- `这一节真正想说明的是`
- `最后用一句话收住`
- `先把这个问题单独拿出来说`
- `继续往下看`
- `我们可以看到 / 我们可以发现`
- `值得注意的是`
- `众所周知`

`可以` 有两种身份，按语境判：“我们可以发现”里是叙事填充，删；“允许/可以这样做”里是规范强度，保留。

只有在过渡位置确实承载信息时才改写，否则删除。

```
弱：接下来我们来看配置同步这一层。
可：配置同步是变更进入执行阶段的第一个稳定边界。
```

## 空话与黑话

做法：先问这句有没有信息；有信息，就换成具体的主体和动作。

| 原表述 | 改写为 |
|---|---|
| 生态 | 具体的依赖、用户、集成方，或归属方 |
| 赋能 | 让 X 能做 Y |
| 闭环 | 从 A 到 B 再回到 A 的具体路径 |
| 抓手 | 团队真正能改变的那个变量或机制 |
| 打通链路 | 谁现在能调用/读取/写入谁 |
| 沉淀 | 知识、规则或产物记录在什么地方 |
| 落地 | 在哪个模块、流程或场景里实现了 |
| 底座 | 基础设施、前置条件或共享模块 |
| 一站式 | 哪几件事能在同一个入口完成 |
| 深度集成 | 确切的集成点和数据/控制流 |
| 无缝 | 不需要额外步骤，或直接删掉 |
| 极致 | 可量化的目标改善了 |
| 全方位 | 列出来是哪几方面 |

## 空泛评价

追问它到底指什么。

| 原表述 | 追问 |
|---|---|
| 高性能 / 低延迟 / 可扩展 | 什么指标、在什么负载下、和谁比？有机制或条件（如“基于零拷贝 IO”）就写出来，没有依据才删 |
| 很清楚 | 从哪条代码路径、哪个指标、哪个例子看出来的？ |
| 很顺 | 成本更低、步骤更少、边界更清楚，还是延迟更低？ |
| 很现实 | 哪个约束在什么条件下出现？ |
| 显然 | 什么证据让它显然？ |
| 真正 | 在证明什么与什么的不同？ |
| 值得 | 在哪个维度、对谁值得？ |
| 影响较大 | 影响了什么，多大？ |

## 句法

- **四字格堆叠**：`高效稳定安全可靠` 这类连排。留一个真的成立的。
- **“进行/实现/完成 + 动词”**：`进行配置` → `配置`，`实现加载` → `加载`，`做出判断` → `判断`。
- **“的”链过长**：`配置的变更的传播的过程的延迟` 这类。拆句或去掉多余的“的”。
- **“不仅……而且……”**：多为强制递进，只保留实际成立的那个。
- **“在……的背景下/基础之上”**：常是铺垫，删掉后重新连句。
- **被动遮住主体**：`配置被推送到 agent` 没说谁推送。主体影响理解且材料里有依据时写明（如原文已给出推送方）；材料没给就留缺口，不凭句式替换。
- **“作为一种……的方式”**：翻译腔，改成直陈。

## 标点与中英混排

- 中文句子用全角标点：`，。：；？！（）`
- 破折号用 `——`（占两字），省略号用 `……`（六点）。中文里破折号是正常标点，不按英文规则禁用；用它代替句号或逗号、或让一句话越拖越长时才处理。
- 中文与英文、数字之间加空格：`使用 Redis 缓存`、`上限 500 条`
- 数字与单位之间加空格：`5 秒`、`30 秒`、`10 MB`
- 引号、括号、书名号成对使用；中文里用全角引号
- 行内代码与相邻汉字之间加空格，紧邻标点时按标点规则：`把 \`cache.enabled\` 置为 \`false\``
- 点号（`，。；：`）不放行首：硬折行时把标点留在上一行末尾。
- 中文标点前后都不加空格；中文句子不混用英文 `,` `.`。英文句子的标点按 `en.md`。
- 数值范围用“至”或 `～`，不用 `-`：`3 至 5 分钟`，不用 `3-5 分钟`（与减号、连字符混淆）。
- 百分号紧跟数字：`80%`；括号内是完整句时句号写在括号内。
- 术语一致：一个概念只用一个中文形式，首次出现再给英文；中英文混排时全程用同一套称呼。
- 不确定的中文限定词是信息，不是冗余：`可能`、`尚未验证`、`需要压测确认`、`约 5 秒` 要保留。但 `我觉得可能应该` 这类叠加要收敛成一个明确表述。

## 口语化痕迹

判据是能否脱离日常语境读懂，不是句子长短。以下五类在中文技术文字里最常见。

| 类型 | 例 | 改写 |
|---|---|---|
| 语气助词 | `改一下吧`、`这样就对啦` | `请修改`、`这样即可` |
| 口头禅与填充 | `其实`、`说白了`、`简单来说`、`然后的话` | 直接给内容 |
| 动作含混的动词 | `搞一下`、`弄掉`、`拿掉`、`打到`、`过一遍` | 指明具体动作：`修改`、`删除`、`发往`、`检查` |
| 模糊量词 | `一堆`、`好多`、`不少`、`各种` | 有数据给数据；没有时保留限定或报告缺口，不为去口语化补造数字 |
| 网络梗与夸张 | `崩了`、`挂了`、`凉了`、`丝滑`、`一坨` | 描述实际状态与可观测现象 |

判据是动词是否说清了动作，不是词表：`跑测试` 这类已成行业惯用语的按项目语境保留，不机械替换；含混时换成具体动作。

符号也在范围内：感叹号、表情符号不进技术文字；波浪号只用作数值范围符。

“空话与黑话”一节处理业务黑话（`赋能`、`闭环`、`抓手`），本节处理随口的说法。两者的改写方式不同：口语替换成对应动作，黑话要换成具体的主体、条件或产物。

## 语体梯度

去口语化过度与放任口语一样是缺陷。目标是中间位置：

| 太随意 | 合适 | 太正式 |
|---|---|---|
| 调这个接口就行，别管别的。 | 调用 `get` 获取用户的电话号码。 | 本页面所述之接口可用于获取用户之电话号码。 |

判据见“口语化痕迹”一节的两条测试：能否脱离日常语境读懂，以及动词是否说清动作。

## 保留内容

去口语化针对的是随口的说法，不是具体信息、判断与真实的限定。以下内容保留：

- 承载信息的具体细节：真实上限、非显然的绕行做法、实测数字。
- 文档类型允许的明确判断。
- 真实的限定词：`通常能成功`、`最多可能落后 30 秒`。
- 有褒有贬的评价：`读没问题，写有风险` 比中性的结论更有用。

每句都短而清楚就是正确结果，不必为句式变化而改写。
