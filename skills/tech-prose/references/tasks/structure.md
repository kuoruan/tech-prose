# 文档结构

用户要求审查文档结构，或明确要求重排章节、调整目录、调整标题层级与编号、拆分或合并文档、重组 README 时，读这份。

只审查时只报告结构问题与建议，修改结构仍须用户明确要求。“排版乱”可能指空格标点（措辞），也可能指层级编号（结构）——先问清楚是哪一种。`润色`、`精简`、`太长`、`易读` 只授权措辞层面；结构问题可以指出，但不能据此搬动内容。

## 先定主读者

主要读者是谁、他要完成什么、会按什么顺序找信息。载体分类只是提示：一份 README 常同时服务使用者与贡献者，不必为此拆开。

## 章节与标题

- 标题说明本节讲什么。`概述`、`其他` 这类不提供信息的标题，换成具体标题或直接删掉该节。
- 层级不跳级；一页只有一个一级标题。
- 编号与实际顺序一致；删掉一节后同步重编号。
- 标题唯一，能直接当链接文字。
- 标题结尾不加句号。

## 审查什么

- **重复**：区分冗余重复与必要复述。合并时保留各处的适用条件，以及读者执行任务所需的警告和限制；同一安全警告在安装与部署两节分别出现，可能是有意设计。
- **顺序**：前置条件、限制与警告是否出现在读者需要它们之前。
- **层级**：标题是否反映内容层级，而不是按篇幅切分。
- **导航**：目录、标题与链接能否让读者找到所需内容。
- **归属**：某段内容是否妨碍当前读者的任务。参考细节不必因此拆出去，先判断它对读者是噪声还是必需。

内容形状跟着读者要做的事：

| 读者要做的事 | 内容形状 |
|---|---|
| 第一次接触 | 定位式：是什么 → 怎么装 → 怎么跑 → 去哪找更多 |
| 学会一项操作 | 步骤式：前置条件 → 编号步骤 → 验证结果 |
| 完成具体任务 | 步骤式，省略原理，只留判断点 |
| 查一个准确值 | 参考式：字段、参数、返回值、默认值、限制 |
| 理解一个设计 | 结论 → 约束 → 备选 → 取舍 |

不强加页数上限与固定节序，也不规定一种文档只能服务一类读者。

## 重组时保住信息

- 同文件重组：保留全部事实、限制、例外与条件对应关系；跨节引用随之改到新位置。用户指定的顺序照字面执行。不在指定范围内的章节放到不破坏该顺序的位置，并说明放置理由。
- 跨文件拆分：先明确目标路径与内容范围。未确定承接位置时只提出拆分建议，保留原文件；获授权创建目标文件后，核对内容承接与链接，再移除原处内容。建议路径不作为现存链接。
- 交付：重组后的内容 + 重要变更说明（搬了什么、去了哪里、为什么）。多文件交付时说明哪些文件尚未实际写入，其中的链接要等落地后再核验。

结构调整不改变原文的事实、契约与规范强度。
